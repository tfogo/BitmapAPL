MINIMUM COSTS AND CHOOSING A PATH

A path through a picture

Make an image narrower by choosing which pixels to leave out.

Ordinary resizing squeezes everything. Cropping cuts away a border. Seam carving takes a different route: remove one connected path from top to bottom, then close the gap.

The path, or seam, contains one pixel in each row. Between rows it can move one column left, stay in place, or move one column right.

Give each pixel a cost

We need a way to choose what to remove. Here we reuse Sobel magnitude: a pixel near a sharp brightness change gets a high cost. A pixel in a smooth area gets a low one.

energy ← ImageOps.Energy picture

This cost is often called energy. It is a rough guide, not an understanding of the picture. A faint face can matter more than a strong edge.

Remember the cheapest way here

Choosing the cheapest pixel in each row would let the path jump across the image. Instead, ask each pixel: what is the cheapest connected path that ends here?

On the first row, the answer is just the pixel’s own energy. On the next row, add that energy to the smallest cost among the possible predecessors above it.

Only two predecessors exist at a side edge. We leave the missing one out; we do not wrap around to the other side.

candidateCosts ← previous[candidates]
best ← ⌊/candidateCosts
next[x] ← energy[y;x]+best

APL’s minimum reduction, ⌊/, chooses the cheapest predecessor. Indexing selects the relevant costs. The library repeats this calculation across each row, carrying the cumulative costs downward.

This is dynamic programming. We keep the answer to each smaller problem—the cheapest path to a pixel—so we do not have to enumerate every complete path.

path ← ImageOps.MinimumSeam energy
path.cost               ⍝ cumulative costs
path.parents            ⍝ chosen predecessor columns

Walk backward, then remove

The cheapest entry in the last row tells us where the winning seam ends. Follow its saved predecessor upward until we reach the first row.

If several paths have the same cost, we need a predictable answer. This implementation chooses the lowest predecessor column on a tie, then the lowest endpoint column in the last row.

seam ← path.seam
narrower ← seam ImageOps.RemoveSeam picture

There is one column index per row. We can turn those indices into a Boolean mask and use compress to keep everything else.

⎕IO ← 0
height width ← ⍴picture
keep ← ⍉(⍳width)∘.≠seam
narrower ← (height (width-1))⍴(,keep)/,picture

∘.≠ compares every column number with every seam entry. This outer product makes a table of comparisons. After transposing, each row has a zero at the pixel to remove. Ravel, compress, and reshape close the gaps.

Choose again after every cut

Removing a seam changes which pixels touch. We must compute a new energy map before choosing the next path.

Horizontal removal needs the same algorithm. Transpose the picture, carve vertically, and transpose back.

shorter ← (8 'horizontal') ImageOps.Carve picture

Try the repeated lines and checkerboard. These pictures have little empty space to spare. Paths can erase patterns or bend boundaries. Even in the simpler scene, enough removals eventually reach the object.

This version uses backward energy: the gradients already in the picture. It does not score the new edges created by a removal. More advanced variants account for that cost, protect selected regions, or combine carving with resizing.

The demo uses small grayscale images and caps removal at 16 seams. The library always keeps at least one row or column. A returned seam uses coordinates from its own removal step, because the picture changes after every cut.

We began with arrays of pixel values. Now we have arrays that describe choices: costs, predecessors, paths, and masks. The same APL ideas—indexing, reduction, transpose, and compression—still do the work.

About this walkthrough

Thirty tiny energy maps are checked by enumerating every possible connected path. Eighteen repeated carvings check both orientations and recompute energy after each cut. The browser agrees with executed Dyalog results, including cost tables and tie-breaking.

The method follows the idea of Avidan and Shamir’s Seam Carving for Content-Aware Image Resizing. This implementation uses clamped Sobel L2 magnitude as its energy. The generated scenes and diagrams are original.
