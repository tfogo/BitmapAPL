Pictures as arrays

A picture is an array of numbers. Let’s see what we can do with it.

Imagine a tiny black-and-white picture. Each square has a brightness: zero is black, 255 is white, and everything in between is a shade of gray. Together, these numbers form an array.

APL is a language built around arrays. An expression can describe what to do to an entire picture.

We’ll build up to a blur, then turn the same idea into an edge detector. The symbols will appear a few at a time. You don’t need to know APL to follow along.

Giving numbers a shape

Our picture has five rows and seven columns. In APL, ⍴ asks for that shape. Put a shape on its left, and the same symbol arranges a list of values into an array.

⍴picture             ⍝ 5 7
picture ← 5 7⍴values  ⍝ arrange 35 values into rows

The little ⍝ starts a comment. It is a note for us, not part of the calculation.

Once the values have a shape, arithmetic keeps that shape. For example, subtracting the picture from 255 exchanges light and dark. Every value changes at once.

negative ← 255-picture

This is called scalar extension: the single number 255 participates in the subtraction at every position. The result is another array of the same shape.

Moving the values instead

We can also change where the values live. A transpose exchanges rows and columns: the third value in the first row becomes the first value in the third row.

transposed ← ⍉picture

That small operation will be useful later. If we know how to process rows, transposing lets us use the same operation on columns.

A pixel borrows from its neighbors

So far each result has depended on only one input value. A blur needs a different idea: let a pixel borrow some brightness from the pixels around it.

Let’s look at just one row. For each position, take a quarter of the value on the left, half of the value in the middle, and a quarter of the value on the right. Add the three contributions.

The three weights add up to one. That matters: if all three pixels have brightness 100, their weighted sum is still 100. A blur should not make a uniform patch brighter or darker.

weights ← 0.25 0.5 0.25
+/weights×neighbors

Read the second line from right to left: multiply the weights by the neighboring values, then add the products. The / turns addition into a reduction—many values become one.

At the ends of the row, a neighbor is missing. Here we repeat the edge value. This rule is called clamping. Filling the missing positions with zeros would darken the ends instead.

Choosing the weights

Our three weights made nearby pixels matter more than distant ones. A Gaussian does the same thing with a smooth, bell-shaped distribution. Sample it at integer pixel offsets, then divide every sample by their sum.

Increasing sigma spreads the influence over more neighbors. The radius is a separate choice: it says how far we look. For this example we keep the radius fixed so you can see sigma’s effect on its own.

⎕IO ← 0                 ⍝ start indexing at zero
x ← (⍳9)-4              ⍝ offsets: ¯4 ¯3 … 3 4
k ← *¯0.5×(x÷sigma)*2
k ← k÷+/k               ⍝ make the weights sum to one

Here ⍳9 generates nine consecutive indices. APL’s * means exponential when used on the right-hand expression alone, and power when it has arguments on both sides. The last line normalizes the weights.

From a row to a picture

A picture has two spatial dimensions. We could give every output pixel a whole square of neighbors. For a Gaussian, there is a useful shortcut: blur across the rows, then blur down the columns. The result is the same as applying the corresponding square Gaussian kernel.

APL has an operator, ⌺, called Stencil, for applying a function to successive neighborhoods. Our row function uses it to calculate the weighted sum at each position. Rank, written ⍤, tells APL which size of cell that function should handle.

⍝ Row handles padding, weighted windows, and cropping
Row ← {(k 'clamp') ImageOps.FilterRow ⍵}
horizontal ← Row⍤1⊢picture
blurred ← ⍉Row⍤1⊢⍉horizontal

The 1 selects vectors—the rows inside the matrix. In the last line, transpose brings the columns into those positions; transpose afterward puts the picture back in its original orientation.

A nine-by-nine filter needs 81 weighted contributions per pixel. Two nine-value passes need only 18. We get the same result with less arithmetic.

The animation blends between the three computed arrays to reveal their shapes. The actual algorithm makes two discrete passes. Brightness is amplified here so the faint values remain visible; the numbers used by the library are unchanged.

What if we subtract?

A blur measures the brightness nearby. To find an edge, we want to measure how much that brightness changes. We can reuse the neighborhood, but give one side negative weights.

Try moving across the boundary below. In a flat region, the two sides cancel. Where the picture changes from dark to light, their difference is positive. Reverse the transition and the sign would reverse too.

difference ← +/¯1 0 1×neighbors

Sobel extends this idea to two dimensions. It measures the difference in one direction while smoothing in the other. Transposing its kernel gives the response in the second direction. We combine those two signed responses into an edge strength.

kx ← 3 3⍴¯1 0 1 ¯2 0 2 ¯1 0 1
ky ← ⍉kx
magnitude ← ((gx*2)+gy*2)*0.5

We started with arithmetic on individual positions. Then we changed the shape, described a neighborhood, and applied a function across rows and columns. Those same ideas let a short piece of APL express an image-processing algorithm.

A picture, a row of weights, and a sum: those are the pieces. APL gives us a way to put them together.
