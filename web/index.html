AN ILLUSTRATED INTRODUCTION TO APL

Reading APL
through pictures

A strange-looking language, a few small expressions, and the pictures they can change.

This is a line of APL:

+/0.25 0.5 0.25×20 60 220

It multiplies three pairs of numbers, then adds the results.

There are no brackets around the lists, and +/ is doing something that may not look like addition. Yet this line contains the main idea behind an image blur.

We’ll learn to read it, then build up to expressions that blur a picture and find its edges. Each new symbol will have something visible to do.

First we need some numbers to work on. In a grayscale picture, each pixel has a brightness from 0 to 255. Move the slider to uncover them.

These rows of numbers form an array. Arrays are APL’s usual working material. That is why pictures make a good way to learn the language.

A list, an arrow, and a shape

In APL, spaces can make a list. The arrow ← gives a value a name:

numbers ← 20 60 220

That is a three-element array. To make a picture, we need rows as well as columns.

Our picture has five rows and seven columns. In APL, ⍴ asks for that shape. Put a shape on its left, and the same symbol arranges a list of values into an array.

⍴picture             ⍝ 5 7
picture ← 5 7⍴values  ⍝ arrange 35 values into rows

The little ⍝ starts a comment. It is a note for us, not part of the calculation.

The familiar minus sign works on arrays too. Subtract the picture from 255, and light and dark exchange places. We don’t need to write a separate subtraction for every pixel.

negative ← 255-picture

This is called scalar extension: the single number 255 participates in the subtraction at every position. The result is another array of the same shape.

⍉ exchanges the axes

Some APL functions have symbols of their own. ⍉ means transpose. It exchanges rows and columns: the third value in the first row becomes the first value in the third row.

transposed ← ⍉picture

That small operation will be useful later. If we know how to process rows, transposing lets us use the same operation on columns.

Reading +/weights×neighbors

Now we can return to the line we started with. It combines several values into one—the operation we need to blur a pixel using its neighbors.

Let’s look at just one row. For each position, take a quarter of the value on the left, half of the value in the middle, and a quarter of the value on the right. Add the three contributions.

The three weights add up to one. That matters: if all three pixels have brightness 100, their weighted sum is still 100. A blur should not make a uniform patch brighter or darker.

weights ← 0.25 0.5 0.25
+/weights×neighbors

APL functions have equal precedence. Without parentheses, they work from right to left. Here, weights×neighbors multiplies matching pairs first. Then +/ adds the products.

The slash is an operator: it changes how a function is applied. + adds two arguments; +/ adds along a list. This is called reduction.

At the ends of the row, a neighbor is missing. Here we repeat the edge value. This rule is called clamping. Filling the missing positions with zeros would darken the ends instead.

Building an array with ⍳

We typed our first three weights by hand. APL can also calculate a whole list of weights from a list of positions. Let’s use a Gaussian: a bell-shaped distribution that gives more weight to nearby pixels.

Increasing sigma spreads the influence over more neighbors. The radius is a separate choice: it says how far we look. For this example we keep the radius fixed so you can see sigma’s effect on its own.

⎕IO ← 0                 ⍝ start indexing at zero
x ← (⍳9)-4              ⍝ offsets: ¯4 ¯3 … 3 4
k ← *¯0.5×(x÷sigma)*2
k ← k÷+/k               ⍝ make the weights sum to one

⍳9 generates the integers 0 through 8 with this index setting. Subtracting four centers them on zero. APL uses the high minus ¯ to write negative numbers.

As with ⍴, the meaning of * depends on its arguments. x*2 squares x; *x computes e to the power x. The final line divides every weight by their sum. There is our +/ again.

Functions that work on functions

A picture has two spatial dimensions. We could give every output pixel a whole square of neighbors. For a Gaussian, there is a useful shortcut: blur across the rows, then blur down the columns. The result is the same as applying the corresponding square Gaussian kernel.

We’ve seen / turn addition into a sum. APL has other operators that tell a function where to work.

⌺, called Stencil, applies a function to successive neighborhoods. ⍤, called Rank, applies a function to cells of a chosen dimension—such as the rows inside a matrix.

We can name a function using braces. Inside them, ⍵ stands for the right argument. Here we wrap the library’s row filter in a function called Row:

⍝ Row handles padding, weighted windows, and cropping
Row ← {(k 'clamp') ImageOps.FilterRow ⍵}
horizontal ← (Row⍤1) picture
blurred ← ⍉(Row⍤1)⍉horizontal

The 1 selects one-dimensional cells: rows. Read the last line from the right. Transpose, filter the new rows, then transpose back. The same row function has now handled both directions.

A nine-by-nine filter needs 81 weighted contributions per pixel. Two nine-value passes need only 18. We get the same result with less arithmetic.

The animation blends between the three computed arrays to reveal their shapes. The actual algorithm makes two discrete passes. Brightness is amplified here so the faint values remain visible; the numbers used by the library are unchanged.

The same expression finds an edge

Keep +/weights×neighbors, but change the weights to ¯1 0 1. Now the expression subtracts the left neighbor from the right. It measures a change in brightness.

Try moving across the boundary below. In a flat region, the two sides cancel. Where the picture changes from dark to light, their difference is positive. Reverse the transition and the sign would reverse too.

difference ← +/¯1 0 1×neighbors

Sobel extends this idea to two dimensions. It measures the difference in one direction while smoothing in the other. Transposing its kernel gives the response in the second direction. We combine those two signed responses into an edge strength.

kx ← 3 3⍴¯1 0 1 ¯2 0 2 ¯1 0 1
ky ← ⍉kx
magnitude ← ((gx*2)+gy*2)*0.5

The symbols should look a little less strange now. ⍴ gives values a shape. ⍉ exchanges axes. +/ combines values. ⍤ tells a function which cells to work on.

Together, they let us describe operations on a whole picture. Changing just the weights took us from softening an image to finding its outlines.
